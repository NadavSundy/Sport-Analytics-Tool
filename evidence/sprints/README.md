# Sprint evidence

Create one directory per milestone/Sprint. Each Sprint directory should make the chronology easy to
follow without forcing a reviewer to open every raw artefact.

## Recommended contents

Retain, where applicable:

- Sprint planning;
- regular stand-up/check-in records;
- stakeholder interactions and feedback;
- review/demo evidence;
- close-out and retrospective records;
- milestone/acceptance evidence; and
- links or references to the relevant Gitea milestone/issues.

Concise Markdown records are the normal navigation layer because they are readable in the repository
and easy to link from the public documentation site.

## Microsoft Teams transcripts

If the original meeting transcript is retained as a Word document:

- keep the `.docx` unchanged as the authoritative source;
- store a same-name `.pdf` beside it when a browser-friendly copy is useful;
- do not silently correct, rewrite, summarise or omit transcript content during conversion; and
- do not convert unrelated Sprint evidence merely to make the formats look consistent.

The public documentation index for these files is
[`docs/process/team-meeting-transcripts.md`](../../docs/process/team-meeting-transcripts.md).

Temporary Word lock files (`~$*.docx`) are not evidence and should not be committed.
