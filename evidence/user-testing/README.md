# User Testing Evidence

Formal user testing follows the task-based process in:

- `docs/testing/user-testing-protocol.md`
- `docs/testing/user-testing-task-bank.md`
- `evidence/user-testing/session-template.md`
- `testing/user-testing/FACILITATOR_SETUP.md` for pre-session state and reusable test inputs

For each round, retain the goal, anonymous participant profile, exact Task IDs attempted, task-by-task outcomes, observations, feedback themes, findings, evaluation decisions, issue/fix traceability and retest evidence.

## Sprint 2

Reviewed Sprint 2 evidence is stored under:

`evidence/user-testing/sprint-2/`

Use:

- `YYYY-MM-DD-PXX-ROLE.md` for individual sessions;
- the same prefix plus a Task ID for supporting screenshots;
- `sprint-2-user-testing-summary.md` for the consolidated result.

The committed Markdown evidence is the authoritative retained record. User-testing evidence is not dynamically retrieved from OneDrive or generated during documentation deployment.

Before committing evidence, remove credentials, personal email addresses and unnecessary identifying information.
