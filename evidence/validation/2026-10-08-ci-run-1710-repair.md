## Repair

The parity test maps transactions onto savepoints in an outer rolled-back
transaction. PostgreSQL `RELEASE SAVEPOINT` preserves `SET LOCAL` settings;
the snapshot writer's 1 ms lock timeout therefore leaked into subsequent reads.
The helper now resets that timeout on simulated commit and asserts that it is
zero before exercising served snapshots. This repairs an identified source of
intermittent read failure without changing production snapshot fallback behavior.
The original intermittent read error did not reproduce locally.

The homepage's new full-section photograph became its mobile LCP element. A
production-preview reproduction scored 82 with a 4.36 s median LCP. Early font
loading reduced layout shifts; route-specific responsive image preloading and
high fetch priority avoid waiting for React to discover the photograph. WebP
copies preserve the existing photograph and credit: 101,632 bytes at 1800 pixels
and 33,204 bytes at 960 pixels, versus the original 283,246-byte JPEG. The
original remains available. The mobile browser requests the smaller variant
once; other routes do not preload or request it.

Lighthouse profiles, floors, run count and failure enforcement are unchanged.
