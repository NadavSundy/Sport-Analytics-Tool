## Requirement-tier interpretation

The final map keeps the original course tiers visible instead of treating later work as a
new requirement: the [Sprint 1 traceability baseline](sprint-1-requirements-traceability.md)
defines the Basic requirement interpretation, the [Sprint 2 traceability record](sprint-2-requirements-traceability.md)
defines the Intermediate one, and the [Sprint 3 record](sprint-3-requirements-traceability.md#selected-advanced-work)
names the deliberately selected Advanced work. A tier label describes the requirement that
the implementation serves; it is not a claim that every capability in a higher tier shipped.

## Shipped natural-language query feature

The public, anonymous `POST /api/v1/natural-language-queries` endpoint and home-page prompt are
**implemented** as an Intermediate query enhancement. A server-side language-model adapter translates
a bounded question into one of the existing published-statistics query definitions, returns the
interpretation with the result, and applies per-client and global limits; it does not calculate a new
statistic or accept analyst-defined expressions. The contract, outcome and privacy boundaries are in
[Analytics Query](../api/analytics-query.md), and the final implementation/evidence path is in
[Natural-Language Query Evidence](../validation/issue-817-natural-language-query-evidence.md).

This is a shipped capability with documented limitations, not a blanket claim that every
natural-language request is answered. The final #868 evaluation runs recorded **62/64** accepted
translations; the remaining delimiter-escape refusal-label issue and variable refusal suggestions,
plus the requested floating assistant, are retained as linked follow-up work in [#924](https://sdp.ms.wits.ac.za/git-push-pray/Sport-Analytics-Tool/issues/924){ target="_blank" rel="noopener" }.
