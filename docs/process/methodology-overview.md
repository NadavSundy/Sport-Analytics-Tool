# Methodology

Stat'sTheGame was developed using a documented, evidence-driven project methodology that combines
iterative Sprint planning, issue-based work tracking, Pull Request review, regular stakeholder
interaction, validation and retrospective improvement.

This section explains both the methodology itself and how its use is demonstrated across the
development lifecycle.

## Project methodology

The [Project Methodology](../project_methodology.md) defines the team's Sprint structure, planning
process, issue workflow, stakeholder interaction, Definition of Ready, Definition of Done, handling of
blocked or incomplete work, Sprint close-out process and methodology review.

The document is retained as the full methodology reference rather than being reproduced here.

## Git methodology

The [Git Methodology](../git-methodology.md) defines the repository workflow used to support the
project methodology, including branch use, Pull Requests, review, integration and release practices.

Keeping the Git methodology separate from the broader project methodology makes the distinction
between development-process governance and source-control practice explicit.

## Methodology in practice

A documented methodology is useful only when it is applied consistently.

[Methodology in Practice](sprint-evidence.md) links the retained Sprint planning, stand-up,
stakeholder, review and close-out records that demonstrate how the methodology was used and adapted
throughout development.

Detailed decisions, validation artefacts, meeting transcripts and historical records are maintained
separately under [Project Records & Evidence](index.md).
